# Update idle gate

Update idle gate (#829, back on orchestrator v2 in #1627): a server update is gated on the server's own turn state, never on process heuristics. The count is `InfinitusRunningTurns.list` (`apps/server/src/infinitus/Layers/InfinitusRunningTurns.ts`: every active thread shell with an `activityRunStatus`, a run waiting on an approval included — it dies with the process too), the one source the HTTP route and the Mac read as well. `packages/contracts/src/server.ts` — `ServerRunningTurn` (`threadId`, `turnId`: the v2 run's id), `ServerUpdateRunningTurnsPolicy` (`refuse` | `wait` | `interrupt`; `runningTurns?` on `ServerSelfUpdateInput`, missing = `refuse`), the `waiting` progress stage with `runningTurns?` (count), and `runningTurns?` on `ServerSelfUpdateError` naming the turns a refusal was over. `apps/server/src/cloud/selfUpdate.ts` — `withUpdateIdleGate` wraps the service that does the update (`layer` composes it; upstream's `withRunningThreadContinuation` is not wired in production since the v2 orchestrator, so the gate does not live there): `refuse` fails at the entry (nothing downloaded for nothing), `wait` downloads first and polls (5 s) at the install hook reporting each change of count, `interrupt` passes; in desktop mode the run itself never waits (the desktop app's update run has a timeout) and `commitDesktopUpdate` gates under the policy the preparation used (an unknown token = `refuse`); `ws.ts` streams the count, `server.ts` provides the running-turns layer. `packages/client-runtime/src/connection/outdatedHostUpdate.ts` — its stage type takes `waiting` too; the outdated-host path sends no policy, so it is refused rather than held.
