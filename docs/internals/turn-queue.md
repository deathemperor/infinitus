## Uploads and pruning

`Normalizer.ts` — the queue commands' uploads stored like a sent message's (and pruned like a reverted message's, #847: a row removed without sending, or an edit that dropped an upload, schedules the thread's attachment prune, whose retained set now counts queued rows' uploads too; a `sent` removal prunes nothing, and the boot-time cleanup replay covers reverts and deletes only, so a crash between the queue event and its prune leaves the copy until the thread is deleted); `apps/server/src/server.ts` — `InfinitusTurnQueueLive` in `ReactorLayerLive` above the interrupt and hold layers it consumes; `Services/InfinitusSessionInterrupt.ts` — `paused` stream (like the hold's `held`).

## The drain

Fork-only: `apps/server/src/infinitus/Layers/InfinitusTurnQueue.ts` (+ `infinitusTurnQueue.logic.ts`, test) — the drain: sends a thread's first row as `thread.turn.start {queuedFrom}` when the thread is idle (`queueDrainVerdict`: no turn running, starting or pending, not held, not paused, not archived, no send of its own in flight; `error` sessions never, see #832), one send per thread at a time; wakes on session-set, the queue events, unarchive, a failed start, a hold or pause letting the thread go, and once at boot after the hold and interrupt layers have published their first lists (5 s cap). A send the decider refuses stays in the queue with an `error` activity `queue.send.failed` and is skipped until edited, moved or removed (the queue blocks behind it; a row already sent or removed only logs); a send the provider fails to start after the row was consumed is put back once, at the head, as `<queueId>~retry` with a fresh message id (its `sendAt` kept) and an `info` activity `queue.requeued` — the drain's own sends only, "Send now" stays a manual send.

## Steer rows (#1318)

A row queued with `sendAt: "tool-boundary"` (the composer's steer mode; the default `idle` is the absent field, so older rows and clients decode) is due while the turn runs too: the drain also watches `tool.completed` activities and, when the row's `turnId` is the shell's `activeTurnId` (a stale event or the next turn's tool is not this turn's step; a subagent's tool counts, as upstream's own boundary counts it), `queueDrainVerdict` sends the FIRST `tool-boundary` row in queue order, past any idle rows ahead of it — head-only would hold a steer behind an idle row until the turn ends, which is what steer exists to avoid. At idle the row is ordinary and the head goes whatever its `sendAt`. The send is a plain `thread.turn.start {queuedFrom}` into the running session, the same shape as "Send now". Every adapter stamps its tool `item.completed` with the turn (Codex from the event, the ACP adapters from `activeTurnId`, OpenCode from the part's turn), so a boundary fires on each provider; an unstamped row is ignored rather than guessed at. A `thread.turn.queue.update` keeps the row's `sendAt` beside its `modelSelection`; an edit through the composer re-queues under the composer's current mode. The server advertises the field as the `turnQueueSendAt` capability: an older server decodes it and sends the row at idle without a word, so a client must gate steer-as-queue on the flag. The phone's steer mode queues the same row on a server that advertises the flag (`threadOutboxQueue.logic.ts` `queuedTurnSendAt`, #1325) and sends into the turn at once on one that does not; its card labels such a row "at next step".
